# SIMURGH

- Code: `src/goal/ml/nn/models/simurgh/dev/monolithic.py`, class `SimurghDev`, one marked section per component; ablation subclasses in `src/goal/ml/nn/models/simurgh/dev/ablations/`.
- Configs: `src/goal/configs/ml/simurgh_dev_<task>.yaml`, one per benchmark task; ablation configs in `src/goal/configs/ml/ablations/simurgh_dev/`.
- Tests: `tests/ml/simurgh_dev/`. Scripts: `scripts/simurgh_dev/`.
- Every key with its default and comment: `references/config_surface.md`. MFC in detail: `references/mfc.md`. The ablation programme: `references/ablation_programme.md`.

## What the model is

A monolithic, conservative message-passing potential (`head: null`, F = −∂E/∂R). The default ACE core builds a body-ordered A-basis from 8 Bessel radial functions (polynomial envelope, p = 5) and spherical harmonics up to l = 3, contracts it to correlation order 3 with a symmetric product basis, and passes L = 2 equivariant messages over 2 interactions within a 5 Å cutoff, at 128 channels. Further energy terms: a two-body pair line φ_ab(r) with a ZBL repulsive wall, radial weights conditioned on the element pair, a smooth attention gate over neighbours, a PGS readout branch and, optionally, factorised electrostatics and a fixed D3(BJ) term. Element references are isolated-atom energies of the labels' level of theory (`atomic_energies.mode: provided`; GMD and 3BPA configs); rMD17 and MD22 configs use `mode: dataset` (least squares on one composition, which removes only a constant).

## MFC in brief

Multi-scale fragment consistency runs the same network on a window cut from the structure and asks the atomic energies of the window's core atoms, and the forces generated by those energies, to match the full-structure values (`objective: [energy, core_force]`, full structure as a stop-gradient teacher). Core atoms are at least `buffer` = r_c = 5 Å from every removed atom, so the loss penalises only dependence carried by message passing, never the first-shell environment. GMD uses half-space windows with 2 levels; long molecules use spheres. Keep MFC only under its rule: OOD force MAE improves by more than 2 s.d. on at least one of Duplication, Fusion and Combination, no task worsens by more than 1 s.d., and ID force MAE stays within 2%. The same engine provides a locality diagnostic for any GOAL model (`scripts/simurgh_dev/mfc_locality.py`).

## ECE core in brief

`core: ece` writes the energy as a sum over directed bonds, with bond states in each bond's own frame (O(2) features labelled by the azimuthal frequency m) updated by bond → atom → bond message passing. The reusable modules are `src/goal/ml/nn/primitives/edge_frame.py`, `src/goal/ml/nn/primitives/o2.py`, `src/goal/ml/nn/blocks/ece.py` and `src/goal/ml/nn/heads/edge_energy.py`. Reference design: arXiv:2609.23134 (LaCour and Head-Gordon). The implementation is native, written from the paper's equations with no code copied from other repositories.

## Optional components

All are off by default and zero-initialised, so switching one on leaves a fresh model unchanged:
- `readout.pgs_edge`: a spectral radial correction to the per-edge tensor-product weights;
- `attention.pan_gate`: a gate on scalar messages from each atom's coordination and angular variance;
- `pair_line.bond_order`: a saturating bond order that scales only the attractive part of a pair term;
- `training.aux.denoise`: denoising of partially corrupted copies, training only (rung D1; the learned-noise rung D2 and the replacement scheme D1-R are planned);
- `training.aux.hessian_distill`: one teacher Hessian row per structure per step, read from the per-atom `hessian` array of the dataset (written by `scripts/labels/hessian_labels.py`). No teacher has been chosen, so no labels exist yet;
- `diagnostics.calm`: an atom-resolved extrapolation grade, output only, built with `scripts/simurgh_dev/extrapolation_grade.py`;
- the float64 L-BFGS stage, `scripts/simurgh_dev/lbfgs_polish.py` (A100, H100 or H200 only; it refuses GPUs named RTX without `--allow-rtx`);
- two ECE branches next to the ACE core (stage 12): `simurgh_dev_abl_ace_ece_fusion` (ACE layers and ECE rounds exchange messages; zero-initialised links) and `simurgh_dev_abl_ace_ece_heads` (an ACE and an ECE energy head, averaged, with an agreement loss; the heads' disagreement is an out-of-distribution score);
- the physical long-range ablation `simurgh_dev_abl_physical_long_range`: dispersion with learned volume ratios, and damped electrostatics with latent charges.

`mfc.tolerance: calibrated` raises until the maintainer supplies the offline calibration file (format in `references/mfc.md`).

## Cost

Measured on an RTX 6000 Ada with a GMD Duplication batch of 48, float32, `kernels: auto` (= e3nn): ACE core B0, 904,834 parameters, 261 ms/step, 13.9 GiB (November 2026; 870k and 249 ms before the PGS readout was corrected); ECE core, 1.17M parameters, 217 ms/step, 7.6 GiB (October 2026). MFC as configured for GMD adds 81% to the step time (41% with `mfc.every_n_steps: 2`, 21% with 4, 51% with `mfc.fraction: 0.5`). `scripts/simurgh_dev/benchmark.py --profile` splits a step by component.

## Design rules

1. Conservative forces only; static DDP graph; new branches zero-initialised so that switching them on leaves a fresh model unchanged.
2. Optional capabilities default to off, unknown keys raise, and every ablation is a one-key diff or one mechanism file.
3. No softmax normalised over atoms or fragments with the envelope applied afterwards. The only neighbour normalisation allowed is `softmax_null`, with the envelope inside the normalisation.
4. No routing on global composition and no maximum-neighbour caps.
5. No sphere-grid activations. The circle-grid activation of the ECE core is allowed under its gauge test. No complex weights in O(2) layers.
6. Isolated-atom element references; never least squares on GMD.
7. Do not supervise population charges. The xTB-charge auxiliary head is parked until the maintainer decides.
8. Validation on in-distribution data only; OOD once per run, at the end.
9. No DFT or other QM calls from the model, the training loop or inference. MFC calibration data come from offline single points supplied by the maintainer.
10. Develop in float32. float64 training and the L-BFGS polish run only on A100, H100 or H200 GPUs.
11. Native code only, and no other model's name anywhere in SIMURGH: cite sources by arXiv ID or DOI and call the external baseline B-REF (`goal-naming-policy`).
12. Do not change the behaviour of legacy models, and do not split SIMURGH into shared GOAL blocks before release, except the ECE modules.
