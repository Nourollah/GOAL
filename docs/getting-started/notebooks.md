# Notebooks

This page lists the Jupyter notebooks in [`notebooks/`](https://github.com/Nourollah/GOAL/tree/main/notebooks), grouped by purpose. For each one you get what it shows, what it needs, and when to reach for it. Use it to choose a starting point, whether you want to learn the API, inspect a trained model, or reproduce one of the case studies.

> [!TIP]
> Notebooks that touch MACE or UPET need the **"GOAL (mace-cuda, standalone)"** kernel (`.venv-mace`), because `mace-torch` pins `e3nn==0.4.4`. Notebooks that load SIMURGH models need a normal GOAL environment (pixi `cuda`, `cpu` or `rocm`; the MD notebooks need the `-full` variant). One kernel cannot do both. See [Installation → MACE](installation.md#mace-mace-torch-in-a-standalone-venv).

## ML tutorials

### `getting_started.ipynb`: from zero to a trained potential

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/getting_started.ipynb). This is a beginner's walkthrough that uses GOAL purely as a Python package, with no YAML and no CLI. In eleven steps it covers installing and importing GOAL, a tour of the moving parts (backbones, heads, losses, data), a self-contained monolithic model, the recommended modular backbone + head composition, reading `.traj` files into `AtomicGraph`s, batching and splitting with PyG DataLoaders, wiring the optimiser, `CompositeLoss` and `GOALModule`, a short training run, saving and reloading checkpoints, and finally using the model as a `GOALCalculator` for single points, a geometry optimisation and a short MD run. It runs on a CPU. Start here if you have never used GOAL.

> [!WARNING]
> The notebook's import cell still references `goal.ml.nn.models.deepset.DeepSet`, a module that no longer exists in the source tree. Until the notebook is updated, substitute an existing invariant backbone, for example `from goal.ml.nn.models.invariant import InvariantGNN` (registry name `invariant_gnn`, the backbone that `custom_dataset_training_tutorial.ipynb` uses).

### `custom_dataset_training_tutorial.ipynb`: your own `.traj` data, three trainers

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/custom_dataset_training_tutorial.ipynb). This notebook generates a synthetic Lennard-Jones dataset (5-, 8- and 13-atom clusters, analytic energies and forces) and writes it to three separate `.traj` files, which mimics data from several independent MD runs. It then loads and merges them with `TrajectoryDataset`, builds an `InvariantGNN` backbone with a custom energy/forces head, and trains the **same model three ways**: `MiniTrainer` (pure PyTorch), the Lightning `Trainer` with `GOALModule` (the production path), and `FabricTrainer` (full loop control, multi-GPU capable). It closes by comparing the three. The workflow carries over directly to real DFT data (VASP, CP2K, MD17, …) if you point `TrajectoryDataset` at your files. The notebook itself is generated by `scripts/gen_tutorial_notebook.py`.

### `diatomic_pair_mlp_tutorial.ipynb`: the smallest possible GOAL model

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/diatomic_pair_mlp_tutorial.ipynb). This notebook learns the Morse potential of O₂ as a function of bond length, a 1-D problem small enough that all the attention goes to GOAL's model contract. You build `AtomicGraph`s by hand, write a monolithic `PairMLPModel` and a custom `PairEnergyForcesHead` that plugs into any backbone, derive conservative forces as $-\partial E/\partial \mathbf{r}$ with autograd, train with `CompositeLoss` (energy + forces), and compare predicted and true energy curves. Read it before [Writing a new model](../ml/models/custom-model.md).

### `feature_extraction_demo.ipynb`: inspecting equivariant representations

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/feature_extraction_demo.ipynb). This notebook builds water and ethanol graphs inline, loads a MACE foundation model and inspects its interaction blocks. It extracts node features at a chosen layer and across all layers (multi-scale), slices out the rotation-invariant L=0 channels with `extract_scalars()`, freezes the backbone with the composable `FrozenBackbone` / `MultiScaleBackbone` wrappers, pools node features to graph level, and wires the frozen backbone into a small downstream training loop. It needs `mace-torch`, so run it in the MACE venv. Companion page: [Feature extraction](../ml/features/feature-extraction.md).

### `mini_trainer_demo.ipynb`: train fast on cached features

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/mini_trainer_demo.ipynb). This notebook extracts features once from a frozen foundation model, caches them as a `TensorDataset`, and trains a downstream MLP head with the standalone `MiniTrainer`, which has per-epoch logging, early stopping, in-memory best checkpoint, LR scheduling, gradient clipping and a `TrainingHistory` for plotting. A synthetic-feature fallback lets it run without MACE. The last section shows `graph_step`, which trains a full backbone + head + `CompositeLoss` on `AtomicGraph` batches with the same trainer. Companion page: [Mini trainer](../ml/features/mini-trainer.md).

## Molecular dynamics

### `md_introduction.ipynb`: a tour of `goal.md`

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/md_introduction.ipynb). This notebook walks through `goal.md`'s usage patterns one section at a time: the direct-import factory pattern (`MoleculeFactory`, `CalculatorFactory`), the `Simulation` class (with ASE's EMT calculator as a dependency-free stand-in), loading a model trained with `goal-train` through the `goal.md.adapters` bridge, converting between ASE and `AtomicGraph`, low-level RESPA multiple time-step MD (fast ML inner loop, slow QM correction every `mts_ratio` steps), the high-level `MTSSimulation`, and adaptive online learning with `QMLearnerCalculator` and `ThresholdPolicy`. It ends with the config-first `goal-simulate` / `goal-simulate-mts` commands. Companion pages: [goal.md overview](../md/index.md), [Usage patterns](../md/guide/usage-patterns.md), [MTS overview](../md/mts/overview.md).

## Model inference and galleries

### `simurgh_gmd_inference.ipynb`: SIMURGH as an ASE calculator

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/simurgh_gmd_inference.ipynb). This notebook loads a trained SIMURGH checkpoint from a GMD-26 FragmentDuplication run and wraps it in a `GOALCalculator`. It runs a sanity check on energy and forces, compares predictions with DFT on an out-of-distribution test structure, relaxes a perturbed geometry with BFGS, runs a short 300 K Langevin NVT trajectory, and does fast batch inference directly on PyG batches with no ASE overhead. Edit the run path at the top to point at your own run under `logs/`. Companion page: [ASE calculator](../ml/deployment/ase-calculator.md).

### `kronos_gmd_inference.ipynb`: legacy KRONOS version

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/kronos_gmd_inference.ipynb). This is the same workflow as the SIMURGH inference notebook, written when the model was still called KRONOS (`logs/KRONOS-GMD/...`). It is kept for reference. Use `simurgh_gmd_inference.ipynb` for new work.

### `nf_simurgh_gmd_inference.ipynb`: fragment-aware inference for NF_SIMURGH

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/nf_simurgh_gmd_inference.ipynb). NF_SIMURGH pools per-atom energies onto fragment virtual nodes, so every graph must carry a `fragment_index`. The stock `GOALCalculator` builds graphs without one, and inference fails with a deliberate error rather than silently degrading to an atom-only model. This notebook defines `NFSimurghCalculator`, a `GOALCalculator` subclass that attaches fragment labels using **the exact fragmentation settings stored in the checkpoint's own config**, so inference can never drift from training. It then repeats the full inference workflow (sanity check, OOD comparison, optimisation, MD, batch inference). Companion page: [NF_SIMURGH](../ml/models/nf-simurgh.md).

### `simurgh_gmd_force_error_gallery.ipynb`: per-frame force-error playback

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/simurgh_gmd_force_error_gallery.ipynb). This notebook gives an interactive py3Dmol playback of five GMD-26 trajectories (2 in-distribution monocarboxylic acids, 3 out-of-distribution dicarboxylic acids) under a trained SIMURGH ARACE model. Each atom carries two glyphs: an inner sphere for the relative force-magnitude error and an outer shell for the directional error (cosine similarity), with every frame Kabsch-aligned to frame 0. The model is loaded from a checkpoint directory with `checkpoint="best"` through the `frozen_source/` snapshot, so it is rebuilt from the code as it was at training time. The notebook ends with an aggregate metrics table and plain ASE calculator usage. Point `CKPT_DIR` at any run to re-render it.

### `mace_foundation_gmd_gallery.ipynb`: MACE-MP zero-shot on GMD-26

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/mace_foundation_gmd_gallery.ipynb). This is the foundation-model twin of the SIMURGH gallery: the same five trajectories, encoding and metrics, but with MACE-MP-0, which has never seen this chemistry. MACE is loaded through two GOAL routes: `BACKBONE_REGISTRY.get("mace_finetune")` (a batchable GOAL backbone that returns energy and forces) and `CalculatorFactory.create("mace", ...)` (the `goal.md` path). Read it side by side with the SIMURGH gallery to compare a task-specific model with a universal one. Runs in the MACE venv. Companion pages: [MACE fine-tuning](../ml/finetuning/mace.md), [MACE, FlashMD & xTB calculators](../md/calculators/foundation.md).

### `upet_petmad_gmd_gallery.ipynb`: PET-MAD zero-shot on GMD-26

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/upet_petmad_gmd_gallery.ipynb). This is the third gallery in the series, with PET-MAD loaded through `CalculatorFactory.create("upet", ...)` (UPET is the renamed `pet-mad` package). PET-MAD is trained at r2SCAN while GMD uses PBE/def2-SVP, so the notebook measures cross-functional transferability: forces are the meaningful comparison, and energies only after a per-element baseline fit. It also tests PET-SPICE, the molecule-trained member of the family, and pins the model `version` so that results do not change when upstream publishes new weights. Runs in the MACE venv with `upet` installed. Companion page: [UPET / PET-MAD](../md/calculators/upet.md).

## Case studies

### MOF-74-Mn / DOBDC series

The three notebooks below form a series that climbs from a single linker molecule to the periodic framework of Mn-MOF-74 (CPO-27-Mn). Intermediate geometries and logs go to `notebooks/dobdc_work/` and `notebooks/mof74_work/`.

#### `dobdc_ligand_properties.ipynb`: the H₄DOBDC linker

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/dobdc_ligand_properties.ipynb). This notebook builds 2,5-dihydroxyterephthalic acid from SMILES (RDKit ETKDG + MMFF94), visualises it in 2D and 3D, converts it to an `AtomicGraph` with `AtomicGraph.from_ase()`, computes MACE-MP energies and forces, and derives HOMO/LUMO, gap and conceptual-DFT descriptors with GFN2-xTB. The GFN2-xTB steps call the standalone `xtb` Python package directly (outside GOAL's calculators), so it must be installed in the notebook's kernel. An optional ORCA B3LYP step adds higher-quality orbital energies. Change `CHARGE` to study the deprotonated forms (−2, −4).

#### `mn_dobdc_complex.ipynb`: the Mn–DOBDC coordination complex

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/mn_dobdc_complex.ipynb). This is the middle level of the series: a `[Mn(DOBDC)(H₂O)₄]²⁻` cluster model of the MOF-74 metal node, with Mn²⁺ chelated bidentately by a carboxylate and a phenolate oxygen and four waters completing the octahedron. The notebook explains why high-spin d⁵ Mn²⁺ (sextet, 5 unpaired electrons) demands unrestricted methods, then analyses metal–ligand binding and LMCT character with GFN2-xTB (unrestricted) and optionally ORCA (multiplicity 6). Like the ligand notebook, it calls the standalone `xtb` Python package directly (outside GOAL's calculators).

#### `mof74_mn_bulk.ipynb`: the bulk periodic framework

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/mof74_mn_bulk.ipynb). The final level is the periodic crystal (space group R-3, 1-D hexagonal channels of about 11 Å). The notebook loads the bundled DFT-relaxed CIF `notebooks/data/CPO27_Mn_qmof-75309dd.cif` (QMOF, 54-atom primitive cell; QMOF live and Materials Project are alternative sources) rather than building the framework by hand. It computes energies and forces with MACE under periodic boundary conditions, optimises the geometry, and outlines periodic CP2K DFT for the electronic structure. It needs the MACE venv, including the `torch.serialization.add_safe_globals([slice])` shim.

### `omol25_explore.ipynb`: browse and search OMol25

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/omol25_explore.ipynb). This notebook is the entry point to the 3,986,754-structure OMol25 `train_4M` split (80 LMDB shards, about 20 GB) through `ASELMDBReader` (random access to rows or `ase.Atoms`) and `ASELMDBCatalogue` (a compact per-row summary that turns searching 4M rows into numpy operations). It shows what the corpus contains (83 elements, charges −8…+9, spins 1…11, total energies of order 10⁴ eV) and why `src/goal/configs/ml/nf_simurgh_omol25.yaml` filters it and needs a per-element baseline. It then demonstrates pulling structures by index, formula, SMILES, provenance or any metadata combination and viewing them in 3D. Build the catalogues first with `python scripts/omol25_prepare.py --root data/OMol25/train_4M --workers 8`, or the first cell spends about ten minutes scanning. Companion page: [ASE-LMDB & OMol25](../ml/data/aselmdb-omol25.md).

### `gmd_cp2k_pw_recompute.ipynb`: plane-wave PBE recomputation with CP2K

[Open on GitHub](https://github.com/Nourollah/GOAL/blob/main/notebooks/gmd_cp2k_pw_recompute.ipynb). This notebook recomputes energies and forces of a GMD FragmentDuplication OOD trajectory with **pure plane-wave** PBE, using CP2K's SIRIUS backend (`method="sirius"` on GOAL's `cp2k` calculator, GTH-PBE pseudopotentials) rather than the default Gaussian-basis GPW. CP2K runs in the `cp2k/cp2k` podman container behind a `cp2k_shell` wrapper. The notebook explains the wrapper's `:z` SELinux relabel and stdout whitelist, adds D3(BJ) dispersion at the ASE level because `&VDW_POTENTIAL` is ignored under SIRIUS, verifies the pipeline on a single frame, and explains why absolute energies are not comparable to the all-electron ORCA reference while forces and relative energies are. The full 200-frame run is handed off to a background script. Companion page: [CP2K](../md/calculators/cp2k.md).
